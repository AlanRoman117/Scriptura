# WCAG 2.2 conformance matrix — `apps/reader`

Every success criterion in WCAG 2.2 (86: 31 Level A, 24 AA, 31 AAA), with its status for the reader PWA. This file is the record; the tests named in the Evidence column are the proof. Update it in the same commit as the change it describes.

**Legend** — ✅ met · ❌ not met (brief named) · 🔧 partly met / re-verify after the named brief · ➖ not applicable (no such content or feature) · 📄 content exemption (applies to scripture and user notes, documented in the help panel) · 🧪 requires a manual check (brief named).

**Preview build (2026-09-17, branch `release/preview-1`).** The reader is published to GitHub Pages as a preview for its translation reviewers, with a notice and a Help section that link to a correction form. Both are covered by the `site` Playwright project (`tests/site/`) in all seven languages: axe, 44px targets, and a phone at 320px. This touches 2.4.3, 2.4.9 and 3.2.5 below. The published site itself is checked under its path, `/Scriptura/`, from files alone.

**Live note editor (2026-09-22, branch `reader/live-notes`).** A note is written in a `contenteditable` region that draws Markdown as it is typed and hides a line's markers unless the caret is on it; plain text stays available in Settings. This touches 1.3.1, 1.3.2, 2.1.1, 2.4.7 and 4.1.2 below. It is a state of its own in the axe gate (every construct drawn, caret on a quote so its dimmed markers are measured), and the phone gates now run with it, which is how they found that the sheet went full only for a textarea. A first version hid markers with `display: none`, which took a heading's `##` out of the accessibility tree; they are now clipped inline and read (1.3.1). Preview is offered only with Plain text. The note is padded so its inset focus ring clears the caret (2.4.7), and each line is `dir="auto"` (1.3.2). Screen-reader behaviour in a real contenteditable (VoiceOver, TalkBack, NVDA) joins the open manual checks.

**Delete confirmation (2026-09-17, branch `reader/confirm-dialog`).** Deleting or removing anything now asks in a modal alert dialog instead of a button that armed in place; this touches 1.4.1, 2.1.2, 2.2.3, 2.4.3, 3.3.4, 4.1.2 and 4.1.3, and the dialog is a state in the axe, target, reflow and text-spacing gates. The same review found that "Start one" on the board screen ignored every pointer press and worked only from the keyboard; it is fixed, and tested with a hit-tested click.

**Interface languages (2026-09-16, branch `reader/i18n`).** The interface is now in English, Spanish, French and Japanese, which touches 3.1.1, 3.1.2, 2.5.3, 3.2.5 and 3.1.5 below. The automated gates run in all four; the non-English copy still needs its native review (docs/plans/reader-i18n/).

**Where it stands (2026-09-12, branch `reader/touch-aaa`).** Of the 86 criteria: 66 met, 18 not applicable (no media, no authentication, no timing), and the two reading-level and pronunciation criteria met for app text and exempt for scripture and notes. None are unmet in the automated record. What is not yet done is the **manual** verification at the bottom of this file — iOS and Android devices, three screen readers, Windows High Contrast — which no CI run can stand in for.

**Scope note.** Conformance is claimed for the application UI and app-authored text. Scripture and user-written notes are content the app presents, not authors: 3.1.5 and 3.1.6 are exempt for them; 3.1.2 (language), 1.4.3/1.4.6 (contrast), 1.4.8 (presentation) and 1.4.10/1.4.12 (reflow, spacing) are still enforced on them.
